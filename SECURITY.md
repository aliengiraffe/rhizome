# Security policy

## Version scope

Rhizome does not currently publish a maintained-version support matrix or a
backport commitment. Reports concerning any version are welcome; include the
exact release or source commit and whether the problem also affects the latest
[release](https://github.com/aliengiraffe/rhizome/releases) or `main`, if known.
This does not promise fixes for older releases or unreleased integrations.

## Report a vulnerability privately

Use GitHub's [Report a vulnerability](https://github.com/aliengiraffe/rhizome/security/advisories/new)
page for this repository (GitHub sign-in required). Private vulnerability reporting
is enabled. Do not open a public issue or pull request with vulnerability details.

Include, when available:

- A description of the vulnerability, impact, and affected versions or commits.
- OS, agent/version, network mode, and relevant configuration with secrets removed.
- Minimal reproduction steps or a proof of concept using disposable data.
- Expected and actual results, and any proposed mitigation.

Do not send credentials, cluster tokens, pairing invitations, private keys,
private transcripts, or unrelated personal information. Use synthetic examples
and sanitized diagnostic excerpts. Do not test against another person's sessions
or devices without permission.

Maintainers can discuss reproduction, remediation, and coordinated disclosure in
the private report. No fixed response time, remediation deadline, or backport
schedule is promised. Keep vulnerability details private while coordinating a
public advisory with maintainers.

For ordinary bugs and feature requests, use the
[issue chooser](https://github.com/aliengiraffe/rhizome/issues/new/choose).
Security advisories are not a channel for conduct complaints.
